## Consumidores y límites comprobados

- `o.window`: instalado líneas 142–154; referencia líneas 213–225. Ambos sólo incorporan el match y llaman a `hl.window_rule`. El nombre no se genera automáticamente.
- Hyprland es una referencia adicional separada: tag `v0.56.2` resuelto al commit [efb50993780079460b0cbed1363e2166a2de1d9f](https://github.com/hyprwm/Hyprland/tree/efb50993780079460b0cbed1363e2166a2de1d9f). [ConfigManager, limpieza](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/config/lua/ConfigManager.cpp#L634) reconstruye registros tras validar sintaxis. [Reglas](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/config/lua/bindings/LuaBindingsConfigRules.cpp#L1190) reutilizan objetos nombrados y registran nuevos anónimos. No identifica los posibles parches del paquete local ni acredita recarga gráfica de Heartchy.
- La [wiki actual de window rules](https://wiki.hypr.land/Configuring/Basics/Window-Rules/) se consultó como apoyo, sin commit fijado; las afirmaciones decisivas sobre registros se apoyan en la fuente fijada anterior.
- Los hooks instalados tienen dispatcher de archivo y directorio `.d`; los callers de theme-set/post-update están identificados. No se añadió ningún hook. El proceso oficial de [update](https://github.com/omacom/omarchy/blob/8e02fc84f5bdc511ed102e2a14f8935bba4f92bd/docs/update-process.md#L117) sigue siendo independiente y puede ejecutar migrations sobre preferencias de usuario. No se promete inmunidad ante futuros cambios.
- Las [fachadas de Shell](https://github.com/omacom/omarchy/blob/8e02fc84f5bdc511ed102e2a14f8935bba4f92bd/agents/skills/shell-dev.md#L12) son contratos acotados. Se inspeccionó además `createScopedPluginShell` del instalado; no se usará una propiedad privada para saltar una API ausente.
